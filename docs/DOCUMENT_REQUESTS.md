# Запросы документов во врезках статей

Посетитель видит «Запросить документ». Открывается отдельная светлая форма с названием выбранного документа, именем, телефоном, почтой и обязательным согласием. Все три контакта обязательны. Это запрос менеджеру, автоматическая выдача файла не добавлена.

Для копирования войдите в `/redaktsiya/`, затем обновите вкладку статьи. Сервер проверяет действующую сессию «Редакции» через `/redaktsiya/document-access.php`. В предпросмотре редактора копирование также доступно. Вход в старую админку DIAFAN не заменяет вход в «Редакцию».

Публичная статья всегда отдаётся в режиме посетителя, чтобы HTML-кэш не раскрывал режим администратора. Ответ проверки доступа — `private, no-store`, без CORS. У посетителей отключены выделение, копирование, вырезание, перетаскивание и контекстное меню внутри врезки; выделение страницы целиком также не позволяет скопировать документ. Обычный текст статьи и поля формы остаются доступны для копирования. Ограничение действует в обычном интерфейсе браузера: открытый HTML нельзя полностью защитить от извлечения через инструменты разработчика, отключение CSS/JS или снимок экрана.

## Заявки и совместимость

Используется существующая форма DIAFAN `site_id=27`, её поля определяются по типам, а не по фиксированным ID. На действующем сайте проверены имя, телефон и email в этой форме. Проверка документа выполняется по опубликованной, активной статье и номеру врезки; переданное посетителем название не принимается на веру. Поддерживаются и старые образцы в blockquote.

Сохраняются действующие проверки согласия, защита от автоматической отправки при автозаполнении, идентификатор повторной отправки, транзакция сохранения заявки, почтовая очередь на `office@nwdelectricity.ru` и очередь интеграции Boykov Services. Письмо оформляется существующим HTML-шаблоном сайта. В письме, CRM и новой редакции видны название документа и статья. В очереди Boykov Services название находится в полях обращения.

Миграции БД и повторная публикация статей не требуются. Контекст документа сохраняется как публичный фрагмент исходного URL заявки: `#nwd-document=<номер>&title=<название в URL-кодировке>`. Он содержит только публичное название документа, без контактов. Функция `nwdDocumentRequestContext()` читает этот формат и учитывает HTML-экранирование URL внутри DIAFAN. Для письма и редакции ссылка преобразуется в обычный якорь `#nwd-document-<номер>`. Снимок названия сохраняется при последующем изменении статьи. Поле `feedback.text`, предназначенное для ответа администратора, не переиспользуется.

Описание Николая в блоге и статьях: `Руководитель ООО «Спецэнергоразвитие».`

## Проверка

`php scripts/test-document-request.php` — изолированные проверки рендера, UTF-8, очистки врезки, обязательных полей, согласия, опубликованности статьи, выбора документа, письма и повторной отправки. БД, почтовая очередь и действия CMS в тесте заменены памятью; внешние отправки отключены. Нужны DOM, mbstring, ctype, iconv. Тест не заменяет интеграционную проверку с локальной БД DIAFAN.

После установки локально:

1. Открыть существующую статью с врезкой в приватном окне. Кнопка — «Запросить документ», копирование врезки заблокировано, обычного текста — доступно.
2. Открыть форму из разных врезок и проверить названия. Все поля и согласие обязательны, согласие при новом открытии снято. Enter в автозаполнении не отправляет заявку.
3. Войти в «Редакцию», обновить статью: доступна кнопка копирования. Проверить также предпросмотр редактора.
4. С `NWD_LOCAL=1` проверить сохранение тестовой заявки, её название документа, источник и почтовую очередь. Убедиться, что внешние отправки отключены.
5. До публикации выполнить проверки репозитория и PHP 7.3 из CI. При серверном обновлении сбросить кэш DIAFAN (включая cache_extreme, если включён), затем проверить один согласованный запрос с реальным получением письма.

В этой среде проверены сборка редактора, 21 серверный сценарий с заглушками, 20 сценариев DOM/JS и реальное окно формы на широкой и мобильной (390 px) странице. Изменённые PHP-файлы прошли синтаксическую проверку PHP 8.4; PHP 7.3 и рабочая БД здесь недоступны. Полный запуск старого ядра на PHP 8.4 не выполняется: его штатная целевая версия — PHP 7.3.
