# Разработка

## Текущее состояние

Исходники и Git подготовлены. Сайт на рабочем сервере не изменялся.
Docker на компьютере владельца на момент подготовки не был установлен.
Локальное окружение, импорт базы и проверка страниц выполняются следующим шагом.
Не считать успешные проверки репозитория подтверждением запуска приложения.

## Что нужно для локальной копии

1. PHP, совместимый с веб-версией 7.3.33; набор расширений уточняется при запуске.
2. Apache с `mod_rewrite` или эквивалентная корректная маршрутизация.
3. Отдельный локальный сервер MySQL-совместимой БД; его версию выбрать по заголовку дампа.
4. `database.sql.gz` из свежего бэкапа и папка `userfls/` из той же копии.
5. Локальный `config.php` на основе `config.example.php` и отдельные локальные правила URL.

Бэкап, созданный в этой сессии, находился на Windows в:

```text
%USERPROFILE%\Downloads\nwdelectricity-backup-20261112-103130-F3P1XCJk
```

Он содержит `site-files.tar.gz`, `database.sql.gz`, контрольные суммы и метаданные.
Вложенный в чат `nwdelectricity.zip` содержит файлы сайта, но не эту выгрузку базы.
Не добавлять бэкап или дамп в папку с исходниками для последующего коммита.

## Конфигурация

Корневой `config.php` нужен приложению, но не хранится в Git.
В полном подготовленном архиве он сохранён как исходный локальный файл;
его действующие доступы не попали в историю. Не запускать копию с этим подключением,
пока не подготовлена и не выбрана локальная база.

В `config.example.php` сохранены совместимые с проектом имена констант,
тема `energo`, `USERFILES=userfls`, префикс `diafan_`, кодировка `utf8mb4`.
Шаблон использует вымышленные локальные доступы и отключает FTP и Memcached.
Фактическое локальное подключение можно передать переменной окружения `NWD_DB_URL`.
CMS не читает `.env` автоматически.

Не выполнять массовую замену домена по всему SQL или всему проекту без разбора:
в CMS могут храниться сериализованные данные, внешние ссылки и настройки интеграций.

## Маршрутизация

Рабочий `.htaccess` отслеживается Git в исходном виде. Для локальной среды
нужно отдельно убрать принудительные переходы на HTTPS и рабочий домен,
сохранив обработку `rewrite`, карты сайта, авторизации и путей модулей.
Эти изменения должны действовать только в локальном окружении.

Для разработки DIAFAN допускает локальное имя без точки, например `localhost`.
Имя рабочего домена и его DNS менять для локальной разработки не требуется.

## Редактирование

- Сначала искать нужный файл в `custom/energo/`, затем его базовый вариант.
- Шапка и подвал — `custom/energo/themes/blocks/`.
- Основной CSS — `custom/energo/css/style.css`.
- Представления форм и услуг — `custom/energo/modules/feedback/views/` и `shop/views/`.
- Контент страниц, параметры блоков и настройки форм — локальная админка/БД.
- Сгенерированные CSS/JS и PHP в `cache/` не редактировать.
- Старые библиотеки не обновлять вместе с несвязанной правкой интерфейса.

## Проверки перед pull request

```powershell
git status --short
git diff --stat
git diff --cached --stat
```

При наличии Python 3.9+:

```text
python scripts/check-repository.py
```

Проверка читает именно содержимое индекса Git: замечает случайно добавленные
локальные настройки, дампы, рабочие данные, крупные файлы, конфликты регистра,
часть явно распознаваемых секретов и BOM в PHP. Это ограниченная проверка,
а не гарантия отсутствия любых секретов или уязвимостей.

При наличии PHP CLI 7.3:

```text
php scripts/lint-php.php
```

Проверка запускает `php -l` для отслеживаемых PHP-файлов и не подключает их как код.
Она не подключается к БД и не запускает обработчики приложения.
В GitHub Actions эти проверки выполняются автоматически.

После настройки локального запуска дополнительно проверить затронутые страницы,
мобильную ширину, меню, модальные окна и формы с тестовыми локальными данными.
Отключить реальные отправки писем, SMS, CRM и другие внешние действия в локальной копии.
Зафиксировать в PR, что проверено фактически и что осталось непроверенным.

## Перенос на рабочий сервер

Публикация — отдельная задача с выбором коммита, резервной копией и проверкой результата.
Не использовать синхронизацию всей папки с удалением отсутствующих файлов:
в Git нет рабочего `config.php`, базы, медиа и остальных данных исполнения.
Не переносить на сайт `.git/`, `.github/`, `docs/`, `scripts/`, локальные данные IDE
и примеры конфигурации как содержимое публичного веб-каталога.
Текущая настройка GitHub Actions ничего не выкладывает на сервер.
