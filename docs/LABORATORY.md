# Электроизмерительная лаборатория

Обновляется существующая страница `/services/elektroizmeritelnaya-laboratoriya/`.
Адрес, ID, модуль DIAFAN, общая шапка, меню, подвал и контакты сохраняются.
На остальных страницах прежний выбор шаблона остаётся без изменений.

Семь блоков и публикационный текст перенесены из ТЗ «003Б — СТРАНИЦА
ЭЛЕКТРОИЗМЕРИТЕЛЬНАЯ ЛАБОРАТОРИЯ». Один H1, шесть H2, каталог из четырёх
групп, пять этапов в порядке 3 + 2, пять вопросов FAQ. На мобильном экране
сохраняется последовательность ТЗ. Полезные материалы скрыты, пока не
опубликованы все три статьи. Ссылки каталога выводятся только для публичных
нативных маршрутов; существующие 16 адресов проверены на HTTP 200.

Новый кадр подготовлен для этой страницы: 1448 × 1086, WebP. SVG-иллюстрации
в блоке стоимости не требуют внешних библиотек. В PDF используется оригинал
двухстраничного свидетельства № 10198, без редактирования. Миниатюра — его
первая страница. PDF расположен в каталоге документов темы на этом же домене.

Форма использует штатный блок обратной связи 27 и четыре существующих поля.
Обязательны телефон и изначально пустой чекбокс согласия; имя, email и описание
необязательны. Отправка требует явного нажатия кнопки. Сохраняются защита от
автозаполнения/Enter, повторных заявок, native HTML-уведомление
`office@nwdelectricity.ru` и существующая очередь CRM/Hub. Нового обработчика
письма или SMTP-настроек нет. Цели Метрики: `etl_price_click`,
`etl_form_submit` (только успешная отправка), `etl_phone_click`.

## Локальная установка

Сначала запустите Docker Desktop и контейнеры проекта:

```powershell
Set-Location 'C:\Users\user\WebstormProjects\nwdelectricity'
docker compose --env-file .local/docker.env -f compose.local.yaml up -d
```

Распакуйте ZIP в отдельный каталог и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$patch\apply.ps1" -ProjectRoot 'C:\Users\user\WebstormProjects\nwdelectricity'
```

Установщик проверяет исходники, сохраняет прежние файлы в
`.local/patch-backups/laboratory-*`, проверяет PHP, формы и рендер через настоящий
парсер DIAFAN. Старый локальный дамп может не содержать лабораторию:
`--bootstrap-local` разрешает создать только эту страницу и только при
`NWD_LOCAL=1`. В production отсутствие существующего маршрута останавливает
установку. Отсутствующие служебные таблицы форм подготавливаются только локально.

Откройте `http://localhost:8080/services/elektroizmeritelnaya-laboratoriya/`
и обновите Ctrl+F5. Локальная проверка не отправляет настоящие письма.

## Публикация GitHub → Beget

После просмотра локального результата:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\tools\laboratory\publish-github.ps1' -ProjectRoot (Get-Location).Path
```

Скрипт коммитит только файлы этой правки от имени владельца, получает main,
выполняет обычное слияние и push без force. Проверка TLS остаётся включённой.
При ошибке сети повторите ту же команду: уже созданный коммит не теряется.
После push скрипт напечатает `GITHUB_MAIN_OK=...` и **полную готовую команду Beget**,
закреплённую за этим коммитом. Команда также записывается в
`$env:TEMP\nwd-laboratory-beget.txt`.

Дождитесь зелёных проверок GitHub Actions. В уже открытой SSH-консоли Beget
вставьте именно напечатанную команду. Загрузка через SCP и FTP не нужна.
Она получает исходники опубликованного коммита, проверяет CI, исходные хеши,
существующий маршрут и форму до активации. После установки проверяет HTTP 200,
текст, title/description/canonical, структуру, форму, ссылки и байты ресурсов.

На сервере исходный контент в БД и пользовательские медиа не удаляются:
новый основной контент выводится отдельным представлением для этого маршрута.
Метаданные и штатное поле `theme=laboratory.php` обновляются в родной записи `site`, `shop_category` или `shop`,
определённой по rewrite. Действующий URL не создаётся заново. Существующая
запись sitemap сохраняется, отсутствующая добавляется для того же элемента.

## Возврат

Каждый запуск сохраняет файлы и приватный JSON для восстановления метаданных.
На сервере путь выводится как `LABORATORY_BACKUP=...`; он находится за пределами
публичной папки. Ошибка после активации запускает возврат метаданных и файлов.
Если запись успели независимо изменить, возврат БД останавливается для ручной
проверки, чтобы не затереть новые правки. Не удаляйте указанный каталог.

## Проверки и ограничения

PHP 7.3: синтаксис, настоящий форматтер SQL-подстановок DIAFAN, native form/render, отклонение невалидных данных и заявок без
согласия, идемпотентность и HTML-уведомление на изолированных адаптерах;
обновление трёх типов маршрутов, повторная установка, возврат и локальное
создание страницы. Отдельно: сверка текста с DOCX, браузерная адаптивность,
JavaScript, состав патча и установщик с имитацией Docker.

Полной базы сайта и SMTP-доступа в рабочей среде нет. Настоящие транзакции MySQL
и доставка писем проверяются в вашей локальной/серверной среде; серверный
установщик выполняет preflight до активации. Рабочие пароли, заявки,
`config.php`, `userfls`, кэш и локальные настройки не входят в архив.

## Исправление ошибок локального отображения

Списки адресов в запросах используют кавычки вокруг строковых подстановок:
DIAFAN `%s` экранирует строку, но не добавляет SQL-кавычки. Тест
`scripts/test-laboratory-queries.php` проходит через настоящий класс `DB` и
проверяет итоговый запрос до передачи драйверу. Публичная проверка отклоняет
ответ с маркерами `[ERROR#...]`. Диагностика CMS остаётся включённой.

Локальная резервная запись копируется по имени сервиса командой Compose `cp`.
Отдельное получение ID контейнера и конвейер с `Select-Object` не используются.
При обновлении уже установленной первой версии принимаются только известные
хеши этой версии; независимые правки по-прежнему требуют проверки.

## Исправление повторного каркаса

Шаблон назначается родной записи лаборатории через поле `theme`, с резервной
копией прежнего значения. Глобальные каркасы `site`, `site_and_order`, `module`,
`module_nobg`, `catalog` возвращены к прежней версии: ранний PHP `return` внутри
DIAFAN завершает только отдельный фрагмент eval и не прекращает вывод каркаса.
Поэтому прежнее подключение выводило второй документ, повторно подключало
скрипты и вставляло предупреждения в атрибуты второго `body`. Браузер переносил
`style="color:red"` из предупреждения на основной `body`.

Проверка `test-laboratory-shell.php` использует целый каркас и штатный парсер,
общие блоки head/header/footer/scripts и нативную форму с изолированными
адаптерами данных. Она выполняется для обычного и мобильного выбора шаблона.
Проверка публичного ответа также отклоняет повторные html/head/body/main,
inline-стиль body, PHP-фрагменты и повторную шапку/подвал.

## Светлые разделы и общая навигация

Абзацная типографика ограничена `main`: размеры подписи логотипа и контактов
снова определяет общая шапка сайта. Хлебные крошки имеют один комплект
отступов, раздельные ссылки и некликабельную текущую страницу с aria-current.
Каталог сохраняет четыре группы, две колонки и текстовые ссылки без отдельных
карточек услуг. Группы отделены цветом и воздухом, без линий между ссылками: основной акцент — тёмная группа измерений с лаймовым заголовком. Номерных плашек нет. По последней правке владельца пять ситуаций оформлены отдельными карточками:
заголовок и описание находятся внутри одного блока. Первый сценарий занимает
всю ширину, остальные четыре образуют две пары. Вступление разделено на два
смысловых фрагмента без изменения текста. Изображений и дополнительных кнопок
в этом разделе нет. Это уточнение владельца заменяет исходное ограничение ТЗ
на карточки в данном разделе.

Этапы имеют небольшие номера, технические SVG-иллюстрации и сетку 3 + 2.
FAQ использует тонкие шевроны без квадратных кнопок и сохраняет нативные details/summary, несколько одновременно открытых
ответов и отсутствие анимации. Тексты, порядок разделов, чёрные hero/стоимость
и исходное свидетельство сохранены.


## Повтор деплоя после ложного отказа публичной проверки

Публичная проверка читает класс и inline-атрибуты из единственного явно
объявленного body. HTML4-разбор libxml иногда создаёт неявный body из-за пикселя
или контейнера счётчика в head и теряет атрибуты исходного body. Остальная
проверка по-прежнему разбирает полный ответ: title, canonical, H1, семь секций,
форму, согласие, FAQ, свидетельство и структурированные данные. Комментарии и
строковые литералы скриптов не считаются дополнительными элементами каркаса.

`scripts/test-laboratory-public.php` воспроизводит этот случай на полном каркасе
страницы и проверяет отклонение действительно неверных ответов. Он не требует
сети, реальной БД, отправки форм и запуска дочерних процессов.

При публикации можно передать `-SavedResponse` с абсолютным путём к `page.html`
из приватного каталога неудачного деплоя. Скрипт GitHub включит этот путь в
готовую команду Beget. Новый деплой сначала проверит сохранённый ответ новым
валидатором и выведет `LABORATORY_SAVED_PUBLIC_OK`. До этого рабочие файлы и БД
не заменяются. Затем выполняется обычная установка и проверка свежего HTTPS-ответа;
при её отказе сохраняется полный механизм отката.
