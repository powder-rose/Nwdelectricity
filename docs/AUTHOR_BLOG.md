# Авторский блог и кодировка статей

Раздел `/articles/` использует существующие страницы DIAFAN и данные редакции.
Адреса, ID, канонические URL, даты публикации и статус статей сохраняются.
Новое оформление включено только для блога; шапка и подвал используют общие
компоненты актуальных внутренних страниц. В настольное и мобильное меню
добавлена ссылка «Статьи» с проверкой существующего пункта.

## Файлы

- `custom/energo/themes/author_blog.php` — публичные выборки, карточки, содержание.
- `custom/energo/themes/blog_index.php` — авторский блок, поиск, темы, страницы.
- `custom/energo/themes/blog_article.php` — статья, автор, содержание, рекомендации.
- `custom/energo/css/author-blog.css` — адаптивное оформление.
- `custom/energo/images/blog/nikolai-boykov-blog.webp` — новый портрет с альфа-каналом;
  костюм без жилета и галстука. Портрет показывается в исходных цветах,
  без фильтра и затемняющего градиента, на светлой подложке. Масштаб
  уменьшен; исходный файл изображения не перекодируется.
- `redaktsiya/lib/encoding.php` — явное указание UTF-8 для DOMDocument и
  консервативное восстановление обратимого UTF-8-as-Latin-1 повреждения.

Публичные запросы проверяют одновременно `status=published`, `deleted=0`,
`site.trash=0` и активность страницы на основном языке. В выдачу не попадают
черновики и ещё не опубликованные материалы. Поиск и темы передаются через
подготовленные SQL-запросы. Список получает ограниченное начало текста и
метаданные, без загрузки всех полных статей или BLOB изображений.

## Кодировка

Санитизация использует отдельный документ с XML-декларацией UTF-8 и
`Content-Type` meta, чтобы повторный разбор при публикации CLI-воркером
не переинтерпретировал кириллицу как Latin-1. Сетевые загрузки libxml запрещены.
Восстановление не переписывает текст: допускается только точное обратимое
преобразование байтов без подстановки/IGNORE/transliteration. Обычный русский
текст и примеры испорченной кодировки внутри здоровой статьи остаются нетронутыми.

Установщик сохраняет приватные копии затронутых файлов, payload статей и
связанных страниц DIAFAN. Изменение данных выполняется в транзакции под тем же
именованным MySQL lock, который использует воркер, и lock строки panel_state.
Восстанавливаются canonical payload и native text основного языка. При изменении
payload увеличивается revision; даты и slug не меняются, черновики не публикуются.
При ошибке до commit выполняется rollback БД и файлов. Ошибка сброса кеша после
commit оставляет согласованные новые файлы и данные: нужно повторить установщик.

Текущая задача Beget CronTab и приватный `article-scheduler.sh` сохраняются.
Системный `crontab` не требуется. Рабочий `config.php`, формы, SMTP и счётчики
не заменяются. Установщик применяет небольшие проверяемые изменения существующих
PHP-файлов и принимает CRLF и дополнительные серверные правки вне изменяемых мест.

`redaktsiya/lib/publication.php` исключён из патча: действующая логика публикации
и обновления активности раздела сохраняется. SEO-данные существующей страницы
`/articles/` обновляются отдельно транзакцией установщика. Исправление UTF-8
находится в санитизации `content.php` и не требует замены publisher.

## Проверено

- PHP 7.3: повторная санитизация и сохранение → расписание → публикация.
- Восстановление трёх реально повреждённых публичных текстов; повторный запуск.
- Поиск, категории, страницы, выдача только опубликованных материалов.
- Настольное и мобильное меню: без дублей, подпись «Статьи».
- Установка поверх версии с таймером, CRLF и дополнительными серверными правками.
- Откат при ошибке данных, отказ при конфликте исходника, повторная установка.

Проверки выполнены на изолированной локальной MariaDB с таблицами DIAFAN.
Это не означает развёртывание на рабочем сервере. Визуальная проверка браузером
в этой среде недоступна: браузер не соединяется с локальным сервером исполнения.
