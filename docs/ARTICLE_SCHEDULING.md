# План публикаций редакции

Адрес: `/redaktsiya/index.php?tab=plan`.

В редакторе три режима: «Черновик», «По расписанию», «Опубликовать сейчас».
Для публикации и расписания нужны заголовок, текст, SEO Title и SEO Description,
а для обложки — Alt. Время вводится и показывается по Москве (Europe/Moscow,
UTC+3), независимо от настроек компьютера.

План публикаций содержит предстоящие статьи, историю последнего результата каждой
статьи, ошибки, поиск по названию и категории. Можно перенести время, вернуть
статью в черновики, опубликовать сейчас или явно повторить ошибочную публикацию.
Конкурирующие действия защищены ревизией статьи и отдельным идентификатором
расписания. Старое завершение задачи не может изменить новое расписание.

Статья со статусом `scheduled` закрыта до срока. Она не включается в публичный
список статей, карту сайта или выдачу изображений для посетителей. При повторном
планировании опубликованной статьи соответствующая страница DIAFAN становится
неактивной. Первая дата публикации сохраняется; для новой статьи, выпущенной
таймером, используется запланированная дата.

## Серверный таймер Beget

На виртуальном хостинге Beget запуск подключается через раздел CronTab панели
управления. Системная команда `crontab` по SSH не требуется и не вызывается.
Установщик создаёт приватный исполняемый файл
`~/.nwd-production/article-scheduler.sh`. В мастере заданий Beget выберите
«Произвольная команда» и добавьте одно задание:

```text
bash ~/.nwd-production/article-scheduler.sh
```

Частота: каждую минуту, то есть `* * * * *`. Существующие задания не меняйте.
Запускатель выбирает проверенный PHP CLI 7.3+, находит каталог сайта и запускает
`redaktsiya/schedule.php --worker`. Один процесс проверяет расписание сразу,
а затем примерно раз в 15 секунд в течение 45 секунд. MySQL GET_LOCK не допускает
параллельных рабочих процессов. Админка и браузер для публикаций не нужны.
После остановки сервера просроченные задачи выполняются при следующем запуске.
Рабочий журнал: `~/.nwd-production/article-scheduler.log`.

Самопроверка `--self-test` проверяет доступ к схеме, не публикует статьи
и не записывает heartbeat. Установщик выводит `ARTICLE_TIMER_FILES_OK`
и `SCHEDULE_CRON_SETUP_REQUIRED`. Автоматический запуск считается подключённым
только после добавления задания в Beget и поступления настоящей проверки.

План показывает фактическую последнюю проверку сервера. При отсутствии проверок
более 90 секунд он сообщает о проблеме с cron. Публикация начинается не раньше
указанного срока; транзакции и обновление кеша требуют дополнительного времени.

Состояния расписания: scheduled, publishing, success, error, cancelled.
Расписание и его последний результат хранятся в `panel_schedule`; состояние
рабочего процесса — в `panel_schedule_worker` с обычным префиксом DIAFAN.
Это две дополнительные таблицы InnoDB. Статьи остаются в `panel_article`,
а страницы и их адреса публикуются через существующий механизм DIAFAN.

Ошибка не запускает бесконечные повторные публикации. В плане доступен явный
повтор. Разрыв между фиксацией страницы в БД и очисткой кеша восстанавливается
при следующей проверке. Завершённой считается публикация после очистки кеша.

## Установка и возврат

Файл `beget-article-timer.txt` целиком вставляется в SSH-консоль Beget. Он
находит каталог сайта, проверяет PHP, сохраняет предыдущие файлы в приватную
`.nwd-production/article-timer-*`, применяет точечные правки, создаёт
дополнительные таблицы и проверяет запускатель. После этого один раз добавьте
задание в CronTab Beget. Повторно создавать то же задание не нужно.

Формы, почтовая конфигурация, счётчики, пароль редакции и существующие статьи
не заменяются. Изменения серверных PHP-файлов применяются по локальным участкам,
с сохранением прочих правок и переводов строк. Если нужный участок изменился,
установка останавливается до активации. Повторный запуск поддерживается.

При ошибке активации предыдущие файлы и запускатель возвращаются, если их
после установки не изменил другой процесс. Дополнительные таблицы сохраняются.
Установщик не отправляет исходники в GitHub. В пакете есть `source.patch`
для исходного репозитория и документация.

Проверки: PHP 7.3, сборка существующего React/Tiptap-редактора, транзакционные
сценарии на отдельной базе MariaDB с родными таблицами DIAFAN, API с авторизацией
и CSRF, серверный таймер, ввод московского времени и взаимодействия календаря.
