## Перелинковка

На странице есть внутренние ссылки на лабораторию и технический отчёт.
На существующей странице лаборатории подключается ссылка из ТЗ в группе
«Кабельные линии и диагностика» блока «Услуги электроизмерительной лаборатории».
Если этой группы ещё нет, добавляются только названия и ссылка из ТЗ;
исходный текст и существующая ссылка на УЗО сохраняются побайтово.
Если группа уже есть как H3 и UL, ссылка добавляется в её список.
Пустой текст, неоднозначная структура или конфликтующая ссылка останавливают
установку до изменения страницы. Повторная установка идемпотентна.

Маршрут лаборатории разрешается через rewrite с учётом module_name и
элемента: site/element, shop/cat или shop/element. Обновление текста и откат
относятся к фактической таблице site, shop_category или shop. Новая страница
и ссылка регистрируются одной транзакцией; исходный текст сохраняется
в приватной резервной копии. Откат проверяет отсутствие последующих правок.
В старом локальном дампе лаборатории может не быть: apply.ps1 явно передаёт
--allow-missing-local-laboratory вместе с NWD_LOCAL=1 и пропускает только
обратную ссылку. На Beget ссылка обязательна; локальный флаг не используется.

## Заявки и аналитика

Используется нативная feedback-форма 27 с существующими ID полей.
Телефон и согласие обязательны; имя, email и перечень инструмента необязательны.
Чекбокс выключен при загрузке. Автозаполнение и Enter не отправляют заявку;
требуется активация кнопки. Повторное нажатие заблокировано во время отправки,
ошибка сохраняет введённые данные. Подтверждение появляется только после
успешного ответа сервера. Сервисная форма не меняет другие формы сайта.
Название услуги и canonical URL задаются сервером; рекламные параметры
ограничены allowlist. Письмо оформляется существующим HTML-шаблоном и ставится
в действующую очередь на office@nwdelectricity.ru; CRM/Hub и защита от дублей
остаются в действующем обработчике. Настройки SMTP патч не меняет.

Метрика 114341229: `elektroinstrument_price_click` при переходе к форме,
`elektroinstrument_form_submit` после подтверждённого сохранения.
В цели не передаются контактные данные. UTM/yclid/gclid сохраняются в сообщении.

## Установка и публикация

Требуется установленный выпуск УЗО, Docker Desktop, `compose.local.yaml`
и `.local/docker.env`. Архив также устанавливается поверх первого варианта
этой страницы: хэши прежнего выпуска включены в допустимые исходники.
ZIP содержит apply.ps1, payload и changes.patch.
Сначала запустить локальный Docker; затем выполнить apply.ps1 с ProjectRoot.
Проверки хэшей выполняются до копирования; копия файлов сохраняется в
`.local/patch-backups/power-tools-*`. Локальная подготовка создаёт только
отсутствующие служебные таблицы заявок и не редактирует существующие.
При ошибке установка восстанавливает файлы и откатывает созданную страницу
по приватной записи `/tmp/nwd-power-tools-*.json`, если транзакция завершилась.

После локальной проверки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\power-tools\publish-github.ps1 -ProjectRoot (Get-Location).Path
```

Скрипт фиксирует только файлы manifest от имени Ekaterina Izotova, проверяет
обычное слияние с main и отсутствие посторонних изменений перед push.
Force-push и отключение TLS не используются. Команда для Beget привязана
к точному опубликованному SHA, выводится в консоль и сохраняется в
`$env:TEMP\nwd-power-tools-beget.txt`. Вставить её в открытую SSH-консоль Beget
после успешных GitHub Checks. Сам скрипт публикации не подключается к Beget.

Сервер проверяет PHP CLI 7.3, GitHub Checks, хэши исходников, зависимости,
маршруты, таблицы и нативную форму до активации. Резервная копия находится
в `~/.nwd-production/power-tools-*`, вне public_html. Активация добавляет
новые файлы перед общими; замена каждого файла атомарна. Ошибка после начала
активации запускает откат. Финальная проверка требует HTTP 200, метаданные,
canonical, форму и CSS новой страницы, доступность двух предыдущих услуг
и обратную ссылку из лаборатории. Рабочий config.php не заменяется.

## Проверки выпуска

В среде подготовки выполнены PHP 7.3 syntax, проверка состава Git и секретов,
сравнение 49 фрагментов публикационного текста с DOCX, нативный рендер через
Parser_theme/контроллер/feedback.model/view с изолированными адаптерами,
серверные сценарии формы, DOM-сценарии JS, регрессии заявок документов,
страниц УЗО и «фаза-нуль», разрешение нативного маршрута лаборатории и
сохранение исходного текста при добавлении ссылки. Установщик проверен
на успешное применение и восстановление при ошибке предвыкатной проверки
с имитированным Docker; это проверка workflow, а не работа с реальной БД.
В браузере проверены desktop, 768, 390 и 320 px, обязательные ошибки формы
и управление FAQ с клавиатуры. Горизонтальной прокрутки нет.

В подготовке нет реальной БД заказчика: транзакция на её данных и настоящая
доставка письма здесь не выполнялись. Их проверка остаётся за локальным
применением и последующим развёртыванием на Beget. GitHub и сервер при
подготовке ZIP не изменялись.
