# Карта проекта

Документ составлен по архиву, полученному 12 ноября 2026 года.
Это обзор структуры и основных точек изменений, а не полный аудит безопасности.

## Запуск и выбор файлов

`index.php` определяет `DIAFAN` и `ABSOLUTE_PATH`, подключает корневой `config.php`,
инициализирует `Custom`, ядро и маршрутизацию. Запросы админки передаются в `adm/`.
Остальные запросы обрабатываются через `Init`.

`includes/custom.php` выбирает файл из применённых тем в `custom/` и использует
базовый файл как запасной вариант. Специальные `.custom.php` могут объединяться
в PHP-кэш. В текущей конфигурации применена одна тема — `energo`.
Стандартная защита PHP-файлов проверяет константу `DIAFAN`, без начального подчёркивания.

## Основные каталоги

| Путь | Назначение | Как работать |
| --- | --- | --- |
| `custom/energo/themes/` | Основные страницы и HTML-каркасы | Первая точка поиска при изменении композиции |
| `custom/energo/themes/blocks/` | Шапка, подвал, head, скрипты, модальные окна | Общие части сайта |
| `custom/energo/themes/functions/` | Переопределённые шаблонные функции | Хлебные крошки, метаданные и дополнительные функции |
| `custom/energo/css/style.css` | Основной CSS активной темы | Главный файл оформления |
| `custom/energo/js/scripts.js` | Подключаемый JS-пакет темы | Сначала проверить состав: в файле есть готовый собранный код |
| `custom/energo/js/site.js` | AJAX, формы и другое поведение DIAFAN | Проверять совместимость с базовым `js/site.js` |
| `js/main.js` | Дополнительное поведение базового сайта | Подключается через блок скриптов при отсутствии переопределения |
| `custom/energo/modules/` | Представления и часть админ-логики модулей | Изменять соответствующее переопределение |
| `modules/` | Штатные модули CMS | Не считать их неиспользуемыми по одной странице сайта |
| `includes/` | Ядро, БД, загрузка, кеширование, парсер | Изменения требуют отдельного разбора |
| `adm/` | Административная часть | Содержит редактор и его библиотеки |
| `themes/`, `css/`, `js/`, `img/` | Базовые шаблоны и ресурсы CMS | Используются как запасные или общие файлы |
| `plugins/` | Поставляемые библиотеки | Сохраняем в Git: манифеста воспроизводимой установки нет |
| `userfls/` | Медиа и документы из админки | Восстанавливать отдельно, не включать в Git |
| `cache/`, `tmp/`, `return/` | Кэш, временные данные, точки возврата CMS | В Git только правила доступа и пустые маркеры |
| `public_html/` внутри корня | Ещё одна копия сайта из архива | Не использовать как рабочий корень и не включать в Git |

исходного кода; их фактическое использование пока не подтверждено.

## Переопределённые модули

- `feedback/views/` — обычные, всплывающие и специализированные формы, включая `t1` и `t2`.
- `menu/views/` — основное, мобильное, сервисное меню, подвал и клиенты.
- `news/views/` и `news/admin/` — списки/детальные новости и изменённая админ-часть.
- `shop/views/` — услуги и связанные блоки, включая `list_responelectric`.
- `site/views/`, `site/admin/` — блоки и дополнительные поля страниц.
- `bs/views/` — представление слайдера.

## Что находится в базе

В шаблонах есть `<insert ...>` с ID блоков, страниц, меню и форм.
Например, главная использует `show_dynamic` для блока `4`, форму для `site_id=31`
и ряд блоков `site`. Значение этих ID и фактические тексты определяет база.
Изменение содержимого через админку не создаёт изменения в PHP-файле.

Поэтому одного клона Git недостаточно для визуального воспроизведения сайта:
нужны локальная база и пользовательские файлы из того же бэкапа.

## Оформление и внешние зависимости

CSS/JS проходят через функции `show_css`, `show_js` и `File::compress`;
редактировать сгенерированные файлы `cache/css` и `cache/js` бессмысленно.
Штатный режим разработки позволяет упростить проверку исходных ресурсов.

В шаблонах обнаружены счётчики Яндекс.Метрики, Google Analytics, Mail.ru и VK,
а также Callibri, callback-виджет и внешние шрифты. Это клиентские интеграции;
их публичные идентификаторы не являются паролями БД. Для локальной среды отдельно
проверять отключение аналитики, отправки форм, писем и других внешних действий.
Бэкап базы в предоставленный ZIP не входит, поэтому настройки интеграций в БД
пока не изучены.

## Сохранённые ограничения

- В `.htaccess` есть принудительный HTTPS, удаление `www`, канонизация
  `index.php`/`index.html` и отдельный редирект PDF на рабочий домен.
- `index.html` используется CMS как файловый запасной вариант главной при проблемах с БД.
- В корне нет автоматической установки зависимостей или конфигурации сборки JS.
  Вложенный `package.json` относится к поставляемой библиотеке jPlayer в редакторе CMS.
- Версия сервера MySQL и номер пакета обновлений DIAFAN требуют отдельной проверки;
  версия `mysqldump 5.7.42` показывает клиент выгрузки, а не обязательно сервер.
- Локальный сайт с восстановленной БД на этапе подготовки Git ещё не запускался.
