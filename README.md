# nwdelectricity.ru

Исходники действующего сайта «Спецэнергоразвитие» на DIAFAN.CMS.
Репозиторий подготовлен из присланного архива 12 ноября 2026 года.

## Что установлено при изучении

| Параметр | Значение |
| --- | --- |
| CMS | DIAFAN.CMS 6.0 по `config.php`; номер установленного пакета обновлений пока не определён |
| Активная тема | `energo` |
| Основные доработки | `custom/energo/` |
| Веб-PHP | Публичный сервер сообщает PHP 7.3.33 |
| PHP в SSH | PHP CLI 5.6.40; это отдельная настройка хостинга |
| База | MySQL-совместимая; при экспорте получены 138 таблиц InnoDB |
| Префикс / кодировка | `diafan_` / `utf8mb4` |
| Загруженный контент | `userfls/` |
| Сборка фронтенда | В корне нет `package.json`, конфигурации Vite и Composer-манифеста; вложенный `package.json` относится к поставляемому jPlayer |

## Открытие в WebStorm

Открой папку с этим README и `index.php` через **File → Open**.
В подготовленном архиве уже есть локальная история Git и ветка `main`.
Проверка из терминала проекта:

```powershell
git status --short
git branch --show-current
git log -1 --oneline
```

Первая команда в исходном состоянии не должна показывать изменений;
вторая должна вывести `main`. Настройки `.idea/` остаются локальными.

## Публикация в GitHub

Для этого коммерческого проекта используем закрытый репозиторий.
В WebStorm выбери **Git → GitHub → Share Project on GitHub**:

- аккаунт: `powder-rose`;
- имя: `nwdelectricity`;
- remote: `origin`;
- **Private**: включено.

Нажми **Share**. Эта команда создаёт репозиторий и отправляет уже подготовленную историю.
Не включай игнорируемые файлы вручную. Если репозиторий с таким именем уже появился,
подключи его по инструкции в [docs/GIT_WORKFLOW.md](docs/GIT_WORKFLOW.md).

## Что хранится в Git

Версионируются ядро CMS, модули, плагины, тема, её изображения и шрифты,
`.htaccess`, `robots.txt`, файлы верификации и инструменты разработки.
В `custom/energo/images/dist/` находятся используемые сайтом изображения;
эта папка намеренно включена в Git.

Из истории исключены:

- рабочий `config.php` и файлы с доступами;
- кэш, временные файлы, логи, архивы возврата CMS и `index.html` — кэш главной;
- загруженные через CMS файлы `userfls/`;
- вложенная копия сайта `public_html/`;
- дампы базы, резервные копии и настройки IDE.

В каталогах исполнения сохранены `.htaccess`, если они были в исходном архиве,
и добавлены `.gitkeep`. Игнорирование не удаляет данные с диска.
В передаваемом полном архиве исходные локальные данные сохранены, но в коммит не входят.
После клонирования из GitHub их нужно восстановить отдельно из бэкапа.

## Локальный запуск — отдельный шаг

Git и открытие проекта в IDE уже подготовлены. Локальный веб-сервер и база
ещё не настроены. В предоставленном ZIP нет дампа базы данных: `database.sql.gz`
остался в отдельном каталоге бэкапа на компьютере владельца.

Перед первым запуском нужна отдельная локальная БД, импорт дампа, восстановление
`userfls/` при клонировании и локальная конфигурация на основе `config.example.php`.
Шаблон содержит пример локального подключения, а не действующие доступы.
Переменная `NWD_DB_URL` берётся из окружения; `.env` автоматически не читается.

Исходный `.htaccess` сохранён для рабочего сайта. В нём есть переходы на HTTPS
и домен `nwdelectricity.ru`; для локального сервера потребуются отдельные правила.
Не подменяй `config.php` и `.htaccess` рабочего сервера локальными вариантами.
Подробнее: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Проверки

```text
python scripts/check-repository.py
php scripts/lint-php.php
```

Первая проверка требует Python 3.9+ и Git; вторая — PHP CLI 7.3.
Они также настроены в GitHub Actions при push в `main` и при pull request.
CI проверяет состав репозитория и PHP-синтаксис, но не заменяет запуск сайта
с базой и визуальную проверку страниц. Автоматического деплоя нет.

При подготовке этого снимка проверены 2277 файлов индекса Git и синтаксис
1255 PHP-файлов интерпретатором PHP 7.3.33. Отдельно проверено, что действующие
доступы из исходного конфига отсутствуют в индексе. Интеграционная проверка
защитного скрипта подтвердила отказ для приватного конфига, фиктивного секрета,
уже добавленного в индекс, и PHP-файла с BOM. Исходные файлы из ZIP сохранены
без изменения байтов; Git нормализует окончания строк согласно `.gitattributes`.
