# Работа с nwdelectricity.ru

## Контекст

- Это действующий PHP-сайт на DIAFAN.CMS; `config.php` сообщает версию `6.0`.
- Активная тема: `energo`. Основная область изменений — `custom/energo/`.
- Веб-сервер сообщал PHP 7.3.33. PHP CLI 5.6.40 в SSH не является веб-версией.
- База имеет префикс `diafan_`, кодировку `utf8mb4`; по экспорту — 138 таблиц InnoDB.
- Папка пользовательских файлов — `userfls`, а не `userfiles`.
- Это не Node/React-проект. Не добавлять npm, Composer или новую CMS без задачи,
  для которой такая смена действительно нужна.
- Сначала прочитать `README.md` и `docs/PROJECT_MAP.md`.

## Правки

- По возможности использовать переопределения в `custom/energo`.
- Для выбора файла проверить `Custom::path()` и наличие переопределения.
  Редактирование базового файла может не повлиять на сайт при наличии файла темы.
- При необходимости изменения ядра, `adm/`, `modules/` или `plugins/` объяснить
  конкретную причину и проверить связанные переопределения.
- Сохранять PHP 7.3-совместимость. Не использовать синтаксис PHP 7.4/8.
- Не форматировать массово старый код, минифицированные файлы и библиотеки.
- PHP-файлы сохранять в UTF-8 без BOM. Не удалять авторские и лицензионные заголовки.
- `custom/energo/images/dist/` — рабочие ассеты, эта папка должна оставаться в Git.
- Вложенная `public_html/` не является корнем этого проекта и исключена из Git.

## Конфигурация и данные

- Не включать `config.php`, дампы, загрузки, кэш, логи и копии сайта в коммиты.
- Не выводить пароли, содержимое рабочего конфига, сессии и реальные заявки в ответы.
- `config.example.php` предназначен для локальной среды; не переносить его настройки
  на действующий сервер как замену рабочего конфига.
- Текущий `.htaccess` содержит рабочие HTTPS/домен-фильтры. Локальные правила
  подготавливать отдельно, не удалять рабочие редиректы ради локального запуска.
- Изменения текстов и настроек через админку сохраняются в БД и не фиксируются
  обычным коммитом файлов. Для задач с данными отдельно описывать порядок переноса.
- Локальные проверки форм проводить с локальной БД и отключёнными внешними отправками.
- Изменения и публикацию на рабочем сервере выполнять в рамках задачи, где это требуется.

## Git и проверки

- Основная ветка — `main`; работа — в коротких тематических ветках.
- Предпочтение владельца: не использовать цифры в названиях веток.
  Примеры: `feat/header`, `fix/mobile-menu`, `chore/local-environment`.
- Коммит должен описывать одну связанную задачу и не захватывать чужие изменения.
- Перед фиксацией смотреть `git status --short` и `git diff --cached --stat`.
- Выполнять `python scripts/check-repository.py` и `php scripts/lint-php.php`
  при наличии соответствующих интерпретаторов; в CI они настроены отдельно.
- Для изменений поведения проверять затронутые сценарии; для оформления — страницы
  на десктопе и мобильной ширине. Не добавлять тесты, дублирующие реализацию.
- Отчёт должен различать проверки состава Git, PHP-синтаксиса и реальный запуск сайта.
- Не считать отсутствие локальной базы успешной проверкой работы приложения.
